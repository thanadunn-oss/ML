# ส่วนโมเดล อธิบายแบบภาษาคน

> **อัปเดต 4 ต.ค. 2569:** เปลี่ยนข้อมูลเป็น **HAM10000 (10,015 ภาพ, 7 คลาส)** แบ่งตาม lesion_id · gate เปลี่ยนเป็น optimizing (val Macro F1) + 2 gate (melanoma recall/precision, CPU latency) — ดูตัวเลขล่าสุดใน `MODEL_CARD.md` และ `HAM10000_VSCODE_GUIDE.md` · หลักการทุกขั้นในเอกสารนี้ยังเหมือนเดิม ส่วนตัวเลขและจำนวนคลาสด้านล่างบางจุดเป็นของชุด ISIC 2024 เดิม


เอกสารนี้อธิบายว่า `src/models/train.py` ทำอะไร ทีละขั้น พร้อมเหตุผล
อ่านจบแล้วควรเขียนใหม่เองได้ด้วยไลบรารีอะไรก็ได้ โดยได้ผลใกล้เคียงกัน

## ภาพรวมในหนึ่งย่อหน้า

เรามีภาพรอยโรคผิวหนัง 963 ภาพ แบ่งเป็น 5 ชนิด เราเอาโมเดลที่ "เคยเห็นภาพทั่วไปมาแล้วเป็นล้านภาพ" (pretrained บน ImageNet) มาสอนต่อให้แยก 5 ชนิดนี้ (transfer learning) ระหว่างสอนจะวัดผลกับชุด validation ทุกรอบ แล้วเก็บรอบที่ดีที่สุดไว้ ส่วนชุด test เก็บไว้วัดครั้งเดียวตอนจบ

```
ภาพ (.jpg) ─► ปรับขนาด + ปรับค่าสี ─► โมเดล ─► คะแนน 5 คลาส ─► เลือกคลาสที่คะแนนสูงสุด
                                                         └─► ถ้าคะแนนสูงสุด < 0.6 → ส่งให้คนตรวจ
```

## ขั้นที่ 1 — ข้อมูลเข้า

| ไฟล์ | คืออะไร |
|---|---|
| `data/model_images/*.jpg` | ภาพ 1,068 ภาพ ชื่อไฟล์ = isic_id |
| `data/splits.csv` | แต่ละภาพอยู่ชุดไหน (train/val/test) และเป็นคลาสอะไร |
| `configs/class_mapping.json` | รายชื่อ 5 คลาส **ตามลำดับ** และวิธีแปลงชื่อโรคละเอียดเป็นคลาส |

**ลำดับคลาสสำคัญมาก:** `nevus, bcc, melanoma, keratosis, scc` → โมเดลตอบเป็นตำแหน่งที่ 0–4
ถ้าใครสลับลำดับ ผลจะผิดทั้งระบบโดยไม่มี error เตือน

จำนวนภาพ: train 674 / val 144 / test 145 (แบ่ง 70/15/15 สุ่มด้วย seed 42 โดยรักษาสัดส่วนคลาส)

---

## ขั้นที่ 2 — เตรียมภาพ (preprocessing)

ภาพจริงมีขนาด ~100–215 px ไม่เท่ากัน ต้องทำให้เหมือนกันก่อนเข้าโมเดล

**ตอนประเมินและตอนให้บริการ (API) — ต้องเหมือนกันทุกตัวอักษร**

1. แปลงเป็น RGB
2. ปรับขนาดเป็น 224 × 224 (ขยายขึ้น เพราะโมเดลที่ยืมมาเคยเรียนที่ขนาดนี้)
3. แปลงค่าสีจาก 0–255 เป็น 0–1
4. ปรับค่าสีด้วย mean = [0.485, 0.456, 0.406], std = [0.229, 0.224, 0.225] (ค่ามาตรฐานของ ImageNet ต้องใช้ให้ตรงกับที่โมเดลเคยเห็น)

**ตอนเทรนเท่านั้น — สุ่มดัดแปลงภาพเพิ่ม (augmentation)** เพื่อให้โมเดลเห็นภาพหลากหลายขึ้น เพราะข้อมูลน้อย

- พลิกซ้าย–ขวา และบน–ล่าง แบบสุ่ม (รอยโรคไม่มี "ด้านบน")
- หมุนสุ่มไม่เกิน 30°
- ปรับความสว่าง/ความต่างสีเล็กน้อย 10% (น้อย เพราะสีช่วยแยก melanoma)

> **ห้าม** ใส่ augmentation ใน API — ภาพเดียวกันต้องได้ผลเดิมทุกครั้ง

---

## ขั้นที่ 3 — สร้างโมเดล

1. โหลดโมเดลสำเร็จรูปพร้อมน้ำหนักที่เรียนจาก ImageNet
   - รอบ 1: ResNet18 (11M พารามิเตอร์)
   - รอบ 2–3: EfficientNet-B0 (4M พารามิเตอร์) ← ตัวที่เลือกใช้
2. ถอด "ชั้นสุดท้าย" เดิมที่ตอบ 1,000 คลาสของ ImageNet ออก แล้วใส่ชั้นใหม่ที่ตอบ 5 คลาส
   - ResNet18: ชั้นชื่อ `fc`
   - EfficientNet-B0: ชั้นชื่อ `classifier[1]`
3. สอนต่อทั้งโมเดล (ไม่แช่แข็งชั้นใด)

**ทำไมใช้โมเดลเล็ก:** ข้อมูลแค่ ~670 ภาพ โมเดลใหญ่จะจำภาพเทรนได้หมดแต่ทายภาพใหม่ไม่ได้ (overfitting) และช้ากว่าเวลาให้บริการ

---

## ขั้นที่ 4 — สอนโมเดล (training)

ทำซ้ำตามจำนวน epoch (1 epoch = เห็นภาพ train ครบทุกภาพหนึ่งรอบ)

1. หยิบภาพ train ทีละ 32 ภาพ (batch) แบบสุ่มลำดับ
2. ให้โมเดลทาย → เทียบกับคำตอบจริงด้วย **CrossEntropy loss** (ยิ่งทายผิดมั่นใจมาก ยิ่งโดนลงโทษมาก)
3. ปรับน้ำหนักด้วย **AdamW** อัตราเรียนรู้ 0.0001 (ต่ำ เพราะน้ำหนักเดิมดีอยู่แล้ว แค่ขยับเล็กน้อย), weight decay 0.0001
4. จบ epoch → ทายชุด **val** ทั้งหมด → คำนวณ **Macro F1**
5. ถ้า Macro F1 ดีกว่าที่เคยดีที่สุด → บันทึกโมเดลเป็น `model.pt`

**Weighted loss (รอบ 3):** คลาสภาพน้อยทายผิดแล้วโดนลงโทษหนักกว่า
น้ำหนักแต่ละคลาส = จำนวนภาพ train ทั้งหมด ÷ (5 × จำนวนภาพของคลาสนั้น)
→ nevus (310 ภาพ) ได้น้ำหนัก ~0.43, scc (51 ภาพ) ได้ ~2.6
ผล: melanoma ถูกจับได้มากขึ้น แต่ nevus ถูกทายเป็น melanoma บ่อยขึ้น

**ทำไมใช้ Macro F1 ไม่ใช้ accuracy:** nevus มีเกือบครึ่ง ถ้าโมเดลตอบ nevus ทุกภาพ accuracy ยังได้ ~46% ทั้งที่ไร้ประโยชน์ Macro F1 เฉลี่ยทุกคลาสเท่ากัน คลาสเล็กจึงมีน้ำหนักเท่าคลาสใหญ่

---

## ขั้นที่ 5 — ประเมินผล

| ชุด | ใช้ทำอะไร | ใช้เมื่อไร |
|---|---|---|
| train | สอนโมเดล | ทุก epoch |
| val | เลือก epoch ที่ดีที่สุด, เลือกโมเดล, เลือกเกณฑ์ส่งทบทวน | ทุก epoch |
| test | วัดผลสุดท้าย | **ครั้งเดียว** หลังเลือกทุกอย่างเสร็จ (`--final-eval`) |

**ทำไมห้ามใช้ test เลือก:** ถ้าลองหลายโมเดลแล้วเลือกตัวที่ test ดีที่สุด ตัวเลข test จะดูดีเกินจริง เพราะเราเลือกตัวที่ "บังเอิญ" เข้ากับ test
หลักฐานจากงานจริง: รันซ้ำโมเดลเดิม test ขยับได้ถึง 0.06

ผลที่บันทึก: Macro F1, Precision/Recall/F1 รายคลาส, Confusion matrix (แถว = คำตอบจริง, คอลัมน์ = ที่โมเดลทาย)

## ขั้นที่ 6 — ผลลัพธ์ที่ได้ (ต่อ 1 run)

```
runs/<วันเวลา>-<arch>/
├── model.pt              น้ำหนักโมเดล (ไม่อยู่ใน Git — เก็บใน MLflow)
├── serving_config.json   ลำดับคลาส, ขนาดภาพ, mean/std, arch → API ต้องอ่านไฟล์นี้
└── metrics.json          ค่าตั้งค่าทั้งหมด + ผล val + ประวัติทุก epoch
```

---

## ขั้นที่ 7 — ใช้งานจริง (สิ่งที่ API ต้องทำ)

1. อ่าน `serving_config.json` → สร้างโมเดลตาม `arch` → เปลี่ยนชั้นสุดท้ายเป็น 5 คลาส → โหลด `model.pt`
2. **สั่ง `model.eval()`** (ปิดพฤติกรรมตอนเทรน ถ้าลืม ผลจะเพี้ยน)
3. เตรียมภาพตามขั้นที่ 2 (แบบไม่มี augmentation)
4. ทาย → softmax → ได้ความน่าจะเป็น 5 ค่า รวมกัน = 1
5. คลาสที่ได้ = ค่าสูงสุด; ถ้าค่าสูงสุด < 0.6 → `needs_review = true`

ตรวจว่าทำถูก: ส่ง 6 ภาพใน `docs/reference_predictions.json` เข้า API ต้องได้คลาสตรงและความน่าจะเป็นต่างไม่เกิน 0.001

---

## ขั้นที่ 8 — ด่านตรวจก่อนอนุมัติ (gate)

ก่อนให้ API ใช้โมเดลรุ่นใหม่ ต้องผ่านครบ 5 ข้อ (`src/models/gate.py`)

1. val Macro F1 ≥ 0.40 — ต่ำกว่านี้ใช้ไม่ได้
2. val Macro F1 ≥ รุ่นที่ใช้งานอยู่ — ห้ามเปลี่ยนไปใช้ของที่แย่กว่า
3. ทุกคลาส F1 > 0 — กันโมเดลที่ทิ้งคลาสใดคลาสหนึ่ง (Macro F1 รวมอาจดูดีแต่ซ่อนปัญหา)
4. ลำดับคลาสตรงกับที่ API ใช้
5. preprocessing_version ตรงกับที่ API ใช้

ไม่ผ่านข้อใด → ปฏิเสธ และ API ใช้รุ่นเดิมต่อ · ใช้ค่า val เท่านั้น ไม่ใช้ test

## สรุปค่าตั้งค่าทั้งหมด (สำหรับเขียนใหม่)

| รายการ | ค่า |
|---|---|
| ขนาดภาพ | 224 × 224 |
| mean / std | [0.485, 0.456, 0.406] / [0.229, 0.224, 0.225] |
| โมเดล | EfficientNet-B0 pretrained ImageNet, ชั้นสุดท้าย 5 คลาส |
| loss | CrossEntropy ถ่วงน้ำหนัก n_total / (5 × n_class) |
| optimizer | AdamW, lr 1e-4, weight decay 1e-4 |
| batch / epochs | 32 / 25 |
| เลือก epoch | best val Macro F1 |
| seed | 42 |
| เกณฑ์ส่งทบทวน | max probability < 0.6 |

ผลที่ควรได้: val Macro F1 ราว 0.42–0.47 — รันจริงสองครั้งได้ 0.417 (GPU) และ 0.468 (CPU) ผลแกว่งตามเครื่อง ดู `model_README.md`
